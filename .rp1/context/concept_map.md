# Domain Concepts & Terminology

**Project**: rp1
**Domain**: AI agent workflow authoring, execution, observability, and project delivery
**Updated**: 2026-05-06

## Core Concepts

| Concept | Type | Definition | Primary Evidence |
|---------|------|------------|------------------|
| Plugin | Container | Distribution unit that groups skills, agents, templates, docs, and install metadata under base, dev, or utils scope. | `docs/concepts/skill-format.md`, `cli/src/catalog/registry.ts` |
| Skill | Workflow entrypoint | Invocable prompt defined by canonical `SKILL.md` frontmatter and body; may be tracked, passive, utility, dispatcher, or agent-only reference. | `docs/concepts/skill-format.md`, `plugins/dev/skills/build/SKILL.md` |
| Agent | Role prompt | Specialized prompt invoked by skills for bounded work such as implementation, review, documentation, security validation, research, or debate participation. | `catalog/agents.yaml`, `plugins/dev/agents/task-builder.md` |
| Tracked Workflow | Runtime process | Stateful skill execution with run metadata, identity arguments, event stream, artifacts, and resume policy. | `cli/src/agent-tools/workflow-bootstrap/index.ts`, `cli/src/agent-tools/emit/database.ts` |
| Workflow Bootstrap | Runtime service | Agent tool that resolves arguments, validates workflow metadata, derives identity, detects host harness, and creates or resumes a run. | `cli/src/agent-tools/workflow-bootstrap/index.ts` |
| Run | State record | Persistent execution record for a workflow, including status, step state, inputs, bootstrap context, artifacts, annotations, and notifications. | `cli/src/agent-tools/emit/database.ts`, `cli/src/agent-tools/workflow-state/index.ts` |
| Event | Runtime signal | Append-only workflow signal for status changes, artifact registrations, annotation updates, user waits, progress updates, and subflows. | `cli/src/agent-tools/emit/models.ts`, `cli/src/agent-tools/emit/index.ts` |
| State Machine | Workflow contract | Mermaid-declared graph whose state ids match emitted step names and whose transitions are enforced for parent workflow steps. | `docs/concepts/skill-format.md`, `cli/src/agent-tools/emit/step-validation.ts` |
| Namespaced Subagent Step | State namespace | Agent-prefixed step such as `task-builder:building` that avoids collision with parent state machines. | `cli/src/agent-tools/emit/step-validation.ts`, `plugins/dev/agents/task-builder.md` |
| Artifact | Workflow output | Registered file or link output associated with a run, relationship, label, storage root, metadata, and stable document identity. | `cli/src/agent-tools/emit/validate.ts`, `cli/web-ui/src/server/routes/artifacts-api.ts` |
| Link Artifact | External artifact | URL-backed artifact with `locationKind=url` and `type=link`, used for external references such as reviewed PRs. | `plugins/dev/skills/pr-review/SKILL.md`, `cli/web-ui/src/lib/link-artifacts.ts` |
| Artifact Template | Output contract | Canonical markdown or section template with routing metadata, producer ownership, strictness, conditions, and optional emit hints. | `plugins/base/skills/artifact-templates/SKILL.md` |
| Annotation | Review record | Threaded user or agent note anchored to an artifact by text selection, hidden anchor, or line, with open/resolved/orphaned states. | `cli/web-ui/src/server/annotation-service.ts` |
| Project | Workspace identity | rp1-enabled workspace identified by `.rp1/project_id` with deterministic project, KB, work, and code directories. | `cli/src/init/directory-model.ts`, `cli/src/agent-tools/rp1-root-dir/resolver.ts` |
| Project Registry | Dashboard index | SQLite-backed registry of known projects that normalizes paths, handles worktrees, tracks availability, and supports Arcade lookup. | `cli/web-ui/src/server/registry.ts`, `cli/web-ui/src/server/project-lookup.ts` |
| Knowledge Base | Project context | Reusable project documentation under `.rp1/context`, generated by map-reduce analyzers and reconciled against prior state. | `plugins/base/skills/knowledge-build/SKILL.md` |
| Feature | Delivery unit | Durable work unit under `.rp1/work/features` containing requirements, design, tasks, machine task plan, evidence, and readiness. | `plugins/dev/skills/build/SKILL.md` |
| Machine Task Plan | Execution plan | Schema-backed `tasks.json` with task ids, types, dependencies, acceptance refs, status, complexity, and scheduling semantics. | `cli/src/agent-tools/build-task-plan/models.ts`, `plugins/dev/agents/feature-tasker.md` |
| Build Task Unit | Execution batch | Schedulable task set derived from `tasks.json`, respecting dependencies and isolating complex tasks from simple batches. | `cli/src/agent-tools/build-task-plan/index.ts` |
| Builder-Reviewer Loop | Quality process | Task-builder changes code and task-reviewer verifies discipline, accuracy, tests, comments, and persisted task status. | `docs/concepts/builder-reviewer-agents.md`, `plugins/dev/agents/task-reviewer.md` |
| Build Readiness | Release gate | Aggregated release contract using `PASS`, `WARN`, `FAIL`, and `WAITING` outcomes. | `plugins/dev/skills/build/SKILL.md` |
| Change Manifest | Edit boundary | Fail-closed manifest of owned files and hunks used to constrain cleanup and protect unrelated edits. | `cli/src/agent-tools/change-manifest/models.ts` |
| Comment Extraction | Analysis tool | Language-aware scanner that extracts comments from manifest-owned lines or git scopes while excluding generated/protected paths. | `cli/src/agent-tools/comment-extract/extractor.ts` |
| Work Search | Read-side projection | Project-scoped SQLite FTS5 index over Markdown work artifacts, rebuildable from `.rp1/work`. | `docs/reference/base/work-search.md`, `cli/src/agent-tools/work-search/search.ts` |
| Socratic Duel | Debate workflow | Backend-coordinated two-participant debate over read-only Markdown source using locks, leases, bounded turns, and terminal outcomes. | `docs/reference/base/socratic-duel.md`, `cli/src/agent-tools/socratic-duel/models.ts` |
| Prompt Pipeline | Prompt governance | Governed prompt-building pipeline combining terse authoring, constitutional primitives, epistemic stance, validation, and confidence reporting. | `plugins/base/skills/prompt-writer/SKILL.md`, `plugins/utils/skills/build-prompt/SKILL.md` |
| Security Assessment | Analysis workflow | Evidence-bounded security posture review scoped by topic and mapped to standards such as NIST, OWASP, CIS, SLSA, OpenSSF, and AI RMF. | `plugins/base/skills/analyse-security/SKILL.md` |
| Runtime Contract | Frontend integration | Arcade-facing contract exposing base URL, host mode, build identity, cache busting, and reconnect policy. | `cli/web-ui/src/server/runtime-contract.ts` |
| Notification | Workflow side effect | Best-effort message generated from workflow events so users can see status changes without inspecting raw event streams. | `cli/src/agent-tools/emit/index.ts` |

## Terminology Glossary

| Term | Definition | Aliases |
|------|------------|---------|
| `run-id` | Unique workflow run identifier required for state-machine-enabled emits. | `RUN_ID` |
| `run_policy` | Workflow metadata describing whether a skill always creates a new run or resumes by identity. | `runPolicy` |
| `identity_args` | Argument names used to derive stable work identity for resumable workflows. | `identityArgs` |
| `workIdentity` | Canonical identity value computed during bootstrap for matching non-terminal resumable runs. | work identity |
| `storageRoot` | Artifact path base: `absolute`, `project`, or `work_dir`. | artifact storage root |
| `locationKind` | Artifact discriminator; file artifacts resolve paths and URL artifacts represent external links. | artifact location kind |
| `docId` | Stable document identity for artifacts and annotations, often read from `rp1_doc_id`. | document id |
| `CanonicalName` | Fully qualified skill identifier used by catalogs and argument resolution. | canonical skill name |
| `arcade_tracked` | Skill metadata flag controlling whether a workflow appears in Arcade tracked workflow surfaces. | `arcadeTracked` |
| `user_invocable` | Skill metadata flag indicating whether users should invoke the skill directly. | `userInvocable` |
| Resolve Args | Generated argument resolution from schema, user input, settings, env sources, defaults, aliases, and implications. | `resolve-args` |
| `codeRoot` | Directory where source code operations occur; may differ from `projectRoot` for worktrees. | `CODE_ROOT` |
| Namespaced Step | Subagent step containing a colon prefix that bypasses parent workflow transition validation. | agent-prefixed step |
| `unit` | Per-task or per-batch dimension attached to emitted workflow status. | task unit |
| ToolResult Envelope | Structured JSON result convention carrying `ok/data` or `error/code/message`. | tool result |
| `tasks.json` | Machine-readable feature task plan consumed by `build-task-plan` and updated by reviewers. | machine task plan |
| Implementation DAG | Design-time dependency graph used by feature-tasker to derive task ordering and parallel groups. | task dependency graph |
| `documentation_followups` | Explicit docs work discovered during build because build does not own general docs sync. | docs followups |
| Stale KB Gate | Documentation workflow checkpoint that blocks or asks before updating user docs from outdated KB evidence. | KB staleness gate |
| Work Search Sidecar | Rebuildable `.rp1/search.db` projection over Markdown work documents. | search.db |
| ActivitySearch | Search-facing workflow run, artifact, and event representation used for activity lookup. | activity search |
| ArtifactBaseline | Saved artifact content baseline used by the web UI to compute patch diffs safely. | artifact baseline |
| Orphaned Annotation | Annotation whose anchor no longer matches current artifact content. | orphan |
| Socratic Lease | Time-bounded participant claim on a debate write lock that must be refreshed or released. | duel lease |
| Terminal Outcome | Socratic Duel closure such as `ACCEPTED_CONSENSUS`, `DISSENT`, `MAX_TURNS`, `TIMEOUT`, or `INVALIDATED`. | duel outcome |
| Evidence Index | Stable evidence ids for PR metadata, files, diffs, commits, or claims. | evidence ids |
| Confidence Gating | Separating high-confidence findings from lower-confidence observations before final outputs. | confidence gate |
| Governance Budget | Prompt-pipeline limit on prompt surface reserved for governance, validation, and epistemic controls. | budget |

## Cross-Cutting Concerns

- **State discipline**: Bootstrap decisions, run ids, state machines, namespaced steps, and workflow-state summaries avoid implicit progress inference.
- **Artifact traceability**: Templates, explicit `storageRoot`, URL metadata, docIds, and relationships link outputs back to runs.
- **Evidence grounding**: Review, walkthrough, security, research, and architecture outputs use provenance, evidence ids, confidence, or refutation notes.
- **Human gates**: Workflows stop or wait at ambiguity, approval, dirty tree, stale KB, manual verification, and readiness gates.
- **Directory correctness**: Tools resolve `projectRoot`, `kbRoot`, `workRoot`, and `codeRoot` deterministically, including worktrees.
- **Resume safety**: Resumable workflows persist identity args, machine task status, readiness artifacts, run decisions, and events.
- **Edit ownership**: Change manifests, owned hunks, baselines, and dirty-overlap checks define what an agent may modify.
- **Platform portability**: Catalogs and prompts preserve platform-specific naming, harness detection, and host metadata while sharing workflow semantics.
- **Read-side projection safety**: Search and activity indexes are rebuildable projections; canonical truth remains artifacts and event tables.
- **External resource handling**: URL artifacts are preserved as link records and excluded from file-path content checks.
